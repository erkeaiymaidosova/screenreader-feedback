# Журнал разработки

Черновые технические заметки: дата, этап, что сделано, какие решения приняты и почему.

## 2026-11-03: Этап 0, подготовка

### Что сделано

- Проверено окружение: macOS 26.2, Git 2.53.0, Python 3.14.0, Node.js 22.12.
- Созданы структура папок, `README.md`, `.gitignore` и этот журнал.
- Устройства для проверки: iPhone (VoiceOver) и доступное Android-устройство (TalkBack).

### Решения

| Решение | Почему |
| --- | --- |
| Отдельный Git-репозиторий только для папки проекта | Домашняя папка уже является репозиторием с личными файлами и старыми удалёнными репозиториями. Отдельный репозиторий исключает их случайную отправку. |
| Название репозитория `screenreader-feedback` | Короткое и отражает тему исследования. |
| Папки `data/` и `recordings/` исключены из Git | Репозиторий публичный, а данные участников и записи сессий в него попадать не должны. |
| Чистые HTML, CSS и JavaScript без фреймворков и сборщиков | Проект легко понять и запустить, а внешние зависимости не влияют на эксперимент. |
| Локальное имя папки оставлено `ProrotypeScreenReader` | Запись AI-чата привязана к пути папки. На GitHub используется имя `screenreader-feedback`. |

## 2026-11-03: Этап 1, каркас

### Что сделано

- Создана страница с заголовком, кнопкой «Сохранить» и пустой областью `role="status"`.
- Тексты сообщений вынесены в `src/messages.js`.
- Автоматическая проверка в Chrome без окна при ширине 360 и 430 px: область пуста при загрузке, после нажатия содержит текст, фокус остаётся на кнопке, горизонтальной прокрутки нет, высота кнопки 44 px.
- Контраст по расчёту: текст на фоне 17,40:1, текст кнопки 7,84:1 (порог WCAG AA для обычного текста: 4,5:1).

### Решения

| Решение | Почему |
| --- | --- |
| Область `role="status"` есть в HTML с загрузки | Сообщение записывается в уже существующую область, а не вместе с ней. |
| Область скрыта визуально, а не через `display: none` | `display: none` скрыл бы содержимое и от скринридера. |
| Повторное объявление пока не реализовано | Приём «очистить, подождать, записать» относится к условию C1 и будет сделан на Этапе 2. |

- Автоматическая проверка в Chrome без окна при ширине 360 px:

### Решения

| Решение | Почему |

| Приём «очистить, подождать, записать» с паузой 100 мс оставлен, хотя VoiceOver на iPhone повторил сообщение и без него | TalkBack ещё не проверен, а приём входит в описание условия C1. |

| Шаблон вибрации: успех 50 мс, неудача 150–80–150 мс | В описании условия C4 шаблон не задан, выбран предварительно. Требует подтверждения автора. |

## 2026-11-05: Этап 3, задания и блоки

### Что сделано

- Порядки условий вынесены в `src/order.js`, данные заданий в `src/tasks.js`.
- Созданы экраны сессии: настройка, знакомство со звуками, тренировка, 4 блока по 4 задания, пауза, финал.
- В `src/feedback.js` добавлена очистка области статуса через 5 секунд.
- Автоматический проход сессии для P2 в Chrome без окна при ширине 360 px: порядок O2, исход каждого задания совпал с запланированным, число тонов и записей в область соответствует условию, фокус остаётся на нажатой кнопке, ARIA-атрибуты не меняются.
- Проверка квадрата: все 12 упорядоченных пар условий встречаются ровно по одному разу.

### Решения

| Решение | Почему |
| --- | --- |
| Видимый результат скрыт через `aria-hidden` во всех условиях, название кнопки не меняется, `aria-pressed` не используется | Иначе результат можно найти свайпом, и C0 перестанет быть условием без обратной связи. Решение автора. |
| Область статуса очищается через 5 секунд и при смене задания | Перечитать сообщение свайпом можно только короткое время, поэтому различие с C0 и C2 почти исчезает. Решение автора. Нужно проверить, не обрывает ли очистка речь. |
| Настройка включается обычной кнопкой, а не флажком | Флажок сам объявил бы своё состояние и в C0. |
| Ошибка имени в форме задания не связана с полем (`aria-invalid` не используется). На экране настройки ошибка ID связана с полем | В задании ошибка является частью условия. Экран настройки не участвует в эксперименте. |
| Форма отзыва проверяет имя по-настоящему: при заполнении имени после неудачи отзыв отправляется | Сообщение не должно расходиться с тем, что ввёл участник. Фактический исход нужно записывать в журнал отдельно от запланированного. |
| Повторное нажатие на «В избранное» убирает рецепт из избранного | Действие задано как переключатель. В C0 и C2 участник не узнает текст сообщения. Требует подтверждения автора. |
| Фокус переносится на заголовок только при смене экрана | Без этого скринридер теряет позицию на новом экране. Правило «фокус не перемещается» относится к обратной связи. |
| Порядок действий внутри набора фиксирован, неудача стоит на позициях 1, 2, 3, 4 | Позиция и тип неудачи привязаны к позиции блока, а не к условию. |
| Тренировка проходит в условии C3 | В описании условие не задано. C3 знакомит и со звуком, и с речью. Требует подтверждения автора. |
| Вибрация вынесена в отдельный пятый блок с собственным набором, данные помечены как поисковые | Иначе C4 нарушит баланс квадрата. Требует подтверждения автора. |
| Порядки названы O1–O4 | Коды P1–P4 уже обозначают участников. |
