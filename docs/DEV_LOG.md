Черновые технические заметки: дата, этап, что сделано, какие решения приняты и почему.

## 2026-11-03: Этап 0, подготовка

### Что сделано

- Проверено окружение: macOS 26.2, Git 2.53.0, Python 3.14.0, Node.js 22.12.
- Созданы структура папок, `README.md`, `.gitignore` и этот журнал.
- Устройства для проверки: iPhone (VoiceOver) и доступное Android-устройство (TalkBack).

### Решения

| Решение | Почему |
| --- | --- |
| Отдельный Git-репозиторий только для папки проекта | Домашняя папка уже является репозиторием с личными файлами и старыми удалёнными репозиториями. Отдельный репозиторий исключает их случайную отправку. |
| Название репозитория `screenreader-feedback` | Короткое и отражает тему исследования. |
| Папки `data/` и `recordings/` исключены из Git | Репозиторий публичный, а данные участников и записи сессий в него попадать не должны. |
| Чистые HTML, CSS и JavaScript без фреймворков и сборщиков | Проект легко понять и запустить, а внешние зависимости не влияют на эксперимент. |
| Локальное имя папки оставлено `ProrotypeScreenReader` | Запись AI-чата привязана к пути папки. На GitHub используется имя `screenreader-feedback`. |

- В `src/feedback.js` добавлена очистка области статуса через 5 секунд.
- Автоматический проход сессии для P2 в Chrome без окна при ширине 360 px: порядок O2, исход каждого задания совпал с запланированным, число тонов и записей в область соответствует условию, фокус остаётся на нажатой кнопке, ARIA-атрибуты не меняются.
- Проверка квадрата: все 12 упорядоченных пар условий встречаются ровно по одному разу.

### Решения

| Решение | Почему |
| --- | --- |
| Видимый результат скрыт через `aria-hidden` во всех условиях, название кнопки не меняется, `aria-pressed` не используется | Иначе результат можно найти свайпом, и C0 перестанет быть условием без обратной связи. Решение автора. |
| Область статуса очищается через 5 секунд и при смене задания | Перечитать сообщение свайпом можно только короткое время, поэтому различие с C0 и C2 почти исчезает. Решение автора. Нужно проверить, не обрывает ли очистка речь. |
| Настройка включается обычной кнопкой, а не флажком | Флажок сам объявил бы своё состояние и в C0. |
| Ошибка имени в форме задания не связана с полем (`aria-invalid` не используется). На экране настройки ошибка ID связана с полем | В задании ошибка является частью условия. Экран настройки не участвует в эксперименте. |
| Форма отзыва проверяет имя по-настоящему: при заполнении имени после неудачи отзыв отправляется | Сообщение не должно расходиться с тем, что ввёл участник. Фактический исход нужно записывать в журнал отдельно от запланированного. |
| Повторное нажатие на «В избранное» убирает рецепт из избранного | Действие задано как переключатель. В C0 и C2 участник не узнает текст сообщения. Подтверждено автором 2026-11-06. |
| Фокус переносится на заголовок только при смене экрана | Без этого скринридер теряет позицию на новом экране. Правило «фокус не перемещается» относится к обратной связи. |
| Порядок действий внутри набора фиксирован, неудача стоит на позициях 1, 2, 3, 4 | Позиция и тип неудачи привязаны к позиции блока, а не к условию. |
| Тренировка проходит в условии C3 | В описании условие не задано. C3 знакомит и со звуком, и с речью. Подтверждено автором 2026-11-06. |
| Вибрация вынесена в отдельный пятый блок с собственным набором, данные помечены как поисковые | Иначе C4 нарушит баланс квадрата. Подтверждено автором 2026-11-06. |
| Порядки названы O1–O4 | Коды P1–P4 уже обозначают участников. |

## 2026-11-06: Этап 4, журнал и экспорт

### Что сделано

- Создан модуль `src/logger.js`: запись событий, хранение в `localStorage`, подсчёт итогов по заданиям, формирование CSV.
- Создан модуль `src/export.js`: скачивание файла и копирование в буфер обмена.
- Незавершённую сессию можно продолжить после перезагрузки страницы.
- На экране настройки доступны экспорт всех сохранённых сессий и их удаление, на финальном экране экспорт текущей сессии.
- Изменён звук неудачи: квадратная волна, спад от 392 до 262 Гц, громкость вдвое ниже звука успеха.
- Автоматическая проверка в Chrome без окна: полная сессия P3 с перезагрузкой в блоке 1, экспорт трёх файлов. Порядок O3 выбран автоматически, повторные нажатия и время подсчитаны верно, прерванный показ задания отмечен как незавершённый, CSV читается в Python без ошибок, содержимое полей формы в журнал не попадает.

### Решения

| Решение | Почему |
| --- | --- |
| Тип события записывается в каждой строке журнала, а также блок, условие, задание и исходы | Каждую строку CSV можно анализировать отдельно. |
| Кроме четырёх обязательных событий записываются начало, продолжение и конец сессии и прослушивание звуков | Чтобы восстановить ход сессии и найти перерывы. |
| Каждый показ задания получает свой номер `taskRun` | После перезагрузки задание показывается заново. Время считается только внутри одного показа. |
| Записывается номер загрузки страницы `pageLoad` | `performance.now()` начинается с нуля после каждой перезагрузки, поэтому время из разных загрузок сравнивать нельзя. |
| Записываются и запланированный, и фактический исход | В форме отзыва участник может исправить неудачу. |
| Содержимое полей формы не записывается | Участник может ввести своё настоящее имя. |
| Итоги: число нажатий на целевой элемент, повторные нажатия (все после первого), время от первого нажатия до «Следующее задание» | Требования описания эксперимента. |
| Проверочное поведение (свайпы скринридера) не записывается | Свайп переводит курсор скринридера, но страница не получает о нём надёжного события. Озвучивание текста без перехода фокуса тоже не видно странице. Поведение кодируется по записи сессии. |
| Новая сессия помечает незавершённые сессии как брошенные (`abandoned`), их данные сохраняются | Экран настройки предлагает продолжить только последнюю сессию. |
| CSV через запятую, в кодировке UTF-8 со знаком BOM | Стандартный формат для R и Python. BOM помогает Excel правильно показать русские буквы. |
| Копирование: по HTTPS через `navigator.clipboard`, по `http://` запасным способом | `navigator.clipboard` недоступен по адресу `http://` с другого устройства. |
| Звук неудачи: квадратная волна, спад от 392 до 262 Гц | Динамик телефона плохо передаёт частоты ниже 300 Гц. Тон остаётся нисходящим и ниже звука успеха. |

### Решения

| Решение | Почему |
| --- | --- |
| Записывается состояние звука | Если earcon не прозвучал из-за приостановки звука, это будет видно в данных и такое задание можно будет исключить из анализа. Беззвучный режим это значение не показывает. |

| Настоящие сессии проводить с адреса HTTPS (GitHub Pages, Этап 7) | По HTTPS работают `navigator.clipboard` и, вероятно, скачивание. Кроме того, `localStorage` привязан к адресу: данные, сохранённые по `http://IP:8000`, не видны по другому адресу, а IP может смениться. |
| Перед каждой сессией выключать беззвучный режим iPhone | В беззвучном режиме earcon не звучат, а условия C2 и C3 без них теряют смысл. Пункт протокола сессии. |

- Раздел «Журнал с телефона»: JSON, скопированный на телефоне, превращается в CSV событий и итогов на ноутбуке.
- Автоматическая проверка в Chrome без окна при ширине 1280 и 360 px для P4 (порядок O4): ответы сохраняются и восстанавливаются после перезагрузки, предупреждение о повторе места в ранжировании появляется, CSV читается в Python, в том числе заметка с запятой, кавычками и переносом строки. Импорт JSON дал 46 событий и 18 итогов, как в исходном файле. Горизонтальной прокрутки нет, цели не меньше 44 px.

### Решения

| Решение | Почему |
| --- | --- |
| CSV ответов в длинном формате: одна строка на один ответ | Ответы уровня задания, блока и сессии помещаются в один файл. Пустые ответы тоже выгружаются, поэтому видно, что пропущено. |
| Ключи для объединения с журналом телефона: `participantId`, `block`, `taskId` | Совпадают с полями журнала событий. |
| Ранжирование задаётся блокам, а не названиям условий | Участник не знает названий условий и может ссылаться только на порядок блоков. Условие блока записывается в CSV. |
| На странице исследователя видны коды условий и запланированные исходы | Страница открыта только на ноутбуке исследователя. |
| Порядок условий выбирается так же, как на телефоне | Если на телефоне порядок выбран вручную, на ноутбуке нужно выбрать тот же. |
| Варианты ответа — переключатели в группах с подписью (`fieldset` и `legend`) | Скринридер читает вопрос вместе с вариантом, а вводить ответы можно мышью или клавиатурой. |

### Отложено

- Пауза около 2 секунд перед звуком на экране знакомства, чтобы он не накладывался на речь VoiceOver. Предложение автора, будет внесено отдельным обновлением. Условий эксперимента не касается. *Внесено на Этапе 6.*

### Наблюдения пробного прохода автора (iPhone, VoiceOver, ID P3)

- Журнал телефона не содержал столбца `audioState`, хотя код был уже изменён. Safari использовал старые файлы из кеша. Исправлено на Этапе 6: сервер без кеша и номер версии в журнале.
- В блоке 2 («Шорпо», планируемая неудача) журнал записал успех: в момент отправки поле «Имя» было не пустым. При повторной проверке с пустым полем отзыв не отправился, как и задумано.
- Поле «Отзыв» не проверяется: по плану единственная неудача формы — пустое «Имя». Решение автора: проверку не добавлять.

### Решения

| Решение | Почему |
| --- | --- |
| Свой маленький сервер вместо `python3 -m http.server` | Стандартный сервер разрешает браузеру кешировать файлы, и телефон может выполнять старый код. |
| Сервер раздаёт папку проекта независимо от того, откуда запущен | Случайный запуск из домашней папки не откроет доступ к личным файлам. |
| Версия записывается в каждое событие, а не только в начало сессии | После перезагрузки страницы может загрузиться другая версия кода. |
| В объединённой таблице «не уверен» считается несовпадением (`correct = false`) | Простое правило по умолчанию. Исходный ответ остаётся в столбце `participantAnswer`, так что при анализе можно выбрать другое правило. |
| В объединённой таблице берётся последний завершённый показ задания, число показов — в столбце `runs` | После перезагрузки задание показывается заново. |
| Проверка совпадения порядка (`orderCheck`) | Если на ноутбуке выбран не тот порядок, что на телефоне, ответы будут сопоставлены не с теми условиями. |
| Тесты запускаются командой `node --test "tests/*.test.js"` | Без шаблона Node принимает служебный файл `src/feedback-test.js` за тест. |

### Решения

| Файл `.nojekyll` | GitHub Pages по умолчанию обрабатывает файлы генератором Jekyll. Проекту он не нужен, а без него публикация проще и быстрее. |
| Запрет индексации | Прототип не предназначен для случайных посетителей из поиска. Это просьба к поисковикам, а не защита: страница остаётся публичной. |
| Настоящие сессии проводятся с адреса GitHub Pages | Адрес не меняется, в отличие от IP компьютера, поэтому сохранённые в браузере данные не «теряются». |
| Данные участников на сервер не отправляются | GitHub получает только запросы на загрузку файлов страницы: IP-адрес и тип браузера устройства, как любой сайт. Журнал остаётся в браузере. |
